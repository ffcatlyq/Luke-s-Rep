# 罗氏中国 Customer Engagement 部门智能工作平台 — 架构设计

> Demo 范围：Customer Engagement 部门，当前治疗领域为血液（Hematology），服务中央市场 / 区域市场 / 销售管理三类人群，6 个产品。设计目标：可扩展到其他治疗领域与团队。

## 0. 形态与核心原则（最重要）

**形态**：本平台不是另行开发的独立 Web 应用，而是**将 Ona 智能体配置成 CE 部门的工作伙伴**。用户直接在 ONA 界面通过对话使用；本仓库是智能体的**知识库 + 能力库 + 记忆沉淀**。服务三类人群（中央市场 PM / 区域市场 PST / 销售管理层），会话启动时按 `profile.yaml` 识别人群、取对应视角。

**核心分层原则 —— 通用引擎 + 可插拔知识包：**

```
┌─────────────────────────────────────────────────────┐
│  通用层  Universal Engine（跨治疗领域复用，一次搭建）  │
│  ├─ 智能体行为 AGENTS.md：人群/角色/合规红线/产出规范  │
│  ├─ 人群 profile：中央市场 / 区域市场 / 销售管理        │
│  ├─ 技能 Skills：技能内按人群分流，取对应视角          │
│  ├─ 任务流 Task Flows：每类任务的标准执行步骤          │
│  └─ 合规护栏 Compliance：RDPAC/反商贿/MLR 通用规则     │
├─────────────────────────────────────────────────────┤
│  知识包层  Knowledge Packs（可插拔，按治疗领域切换）   │
│  ├─ 🩸 血液 Hematology（demo，先做，兼作模板）         │
│  ├─ 👁 眼科 Ophthalmology（未来）                     │
│  ├─ 🧠 神经科学 Neuroscience（未来）                  │
│  └─ 🛡 免疫 Immunology（未来）                        │
└─────────────────────────────────────────────────────┘
```

**为什么这样分层**：不同治疗领域的**产品知识不同**，但底层**技能与任务流是相同的**——无论血液还是眼科，"生成一份竞品简报"的流程、结构、合规检查完全一致，变的只是填入的产品知识。同理，同一技能对中央市场/区域市场/销售管理三类人群通用，仅在技能内按人群分流取不同视角。因此：

- **技能/任务流/合规护栏 = 通用引擎**，一次做好，所有治疗领域共用，扩展时不改动。
- **知识包 = 可插拔内容**，血液先做一个完整样板，未来新增眼科即"照血液结构再填一个包"。

血液 demo 的真正价值：验证"通用引擎 + 可插拔知识包"模式是否跑通，并成为其他领域的复制模板。

## 1. 定位

面向罗氏中国 Customer Engagement 部门的智能工作平台。**服务三类人群 × 三种角色**。

**三类人群**（会话启动按 `profile.yaml` 识别，详见 `docs/jd-alignment.md`）：

| 人群 | 谁 | 汇报线 |
|---|---|---|
| 中央市场 Central Marketing | PM（IC） | PM → MM → FH |
| 区域市场 PST | PSM / PSL | PSM → PSL → RCL |
| 销售管理 Sales Mgmt | LEL（圈长）及以上 | LEL →（REL）→ RCL |

**三种角色**（三类人群通用，按诉求切换）：

| 角色 | 定位 | 交互模式 | 典型诉求 |
|---|---|---|---|
| **助理** Assistant | 帮我把活干了 | 任务执行 | 起草物料、总结会议、拉数据、准备汇报、排期、团队沟通稿 |
| **参谋** Advisor | 帮我想清楚 | 洞察与决策支持 | 市场/竞品/客户分析、策略推演、业绩归因、"资深视角会怎么看" |
| **赋能** Enablement | 帮我成长/沉淀 | 工具与知识复用 | 模板、Playbook、最佳实践、团队教练、新人上手 |

三类人群、三种角色共享同一套**产品知识库**、**罗氏语境（组织/客户/区域/SOP）**和**合规护栏**。

## 3. 功能模块（领域子智能体）

每个模块是一个可独立演进的领域能力，由编排层按意图调度。

| # | 模块 | 助理能力 | 参谋能力 | 赋能能力 |
|---|---|---|---|---|
| 1 | **品牌策略与规划** | 起草 brand plan / cycle plan 草稿 | 定位、策略 gap 分析、情景推演 | 品牌计划模板、框架库 |
| 2 | **市场与竞争洞察** | 汇总竞品动态、生成竞品简报 | 市场规模测算、竞争格局分析 | 分析框架、数据源清单 |
| 3 | **内容与物料** | 起草推广物料/幻灯/话术 | 信息屋一致性检查 | 物料模板 + MLR 送审前自查 |
| 4 | **KOL 与专家管理** | 专家画像、互动记录整理 | 分层策略、覆盖 gap 分析 | KOL 管理 SOP、合规边界 |
| 5 | **会议与项目管理** | 会议排期、行动项跟踪 | 会议 ROI 评估 | 大会/项目 Playbook |
| 6 | **销售赋能** | 起草 detail aid、FAQ、培训稿 | 一线反馈洞察 | 培训包、异议处理库 |
| 7 | **数据与绩效** | 拉取/汇总销售与市场份额 | 预测、达成归因分析 | 指标字典、看板模板 |
| 8 | **跨部门协作** | 起草跨部门 brief/邮件 | 医学/准入/RWE 协同建议 | 协作流程、RACI 模板 |
| 9 | **预算管理** | 预算表整理、花费跟踪 | 预算分配优化建议 | 预算模板、ROI 框架 |
| 10 | **合规助手** | 物料/话术合规预检 | 灰区风险提示 | RDPAC/内部 SOP 速查 |
| 11 | **客户与覆盖管理** | 客户分层清单、覆盖表 | 分层策略、覆盖 gap、全渠道触点 | 分级模型（C30/T70/T300）、覆盖 SOP |
| 12 | **区域落地**（PST） | 区域计划、活动执行清单 | 区域格局、中央-区域对齐 | 区域计划模板、活动 Playbook |
| 13 | **团队管理与教练**（销售管理） | 1:1 议程、复盘/例会材料 | 业绩归因、辖区/资源优化 | 辅导框架、辖区模型、QBR 模板 |

> 模块 10（合规）同时作为横切护栏嵌入 1–13 的所有生成动作。
> 模块 11–13 服务区域市场与销售管理人群；1–10 为原有能力，三类人群按 profile 取对应视角。

**关键能力**：支持"单品视角"与"franchise 组合视角"双重分析（如 CD20 全周期布局、双抗协同）；并支持"客户/医院分级视角"与"区域辖区视角"，服务区域市场与销售管理人群。

## 5. 合规护栏（红线，横切）

中国医药推广强约束，任何面向外部/一线的生成物必须经过：

1. **声明边界**：不得超适应症（off-label）、不得夸大疗效、须有循证支撑
2. **RDPAC 行业准则** 与 **反商业贿赂** 规则校验
3. **MLR 送审意识**：生成物料标注"送审前草稿"，附自查清单
4. **审计留痕**：所有生成动作可追溯（谁、何时、生成了什么）
5. **数据分级**：区分公开 / 内部 / 敏感数据的可用范围

## 7. Demo 演进路线（建议）

- **阶段一**：产品知识库 + 对话式助理（问答、物料起草、竞品简报）+ 合规护栏
- **阶段二**：参谋能力（市场/竞品分析、策略推演）+ 工作台
- **阶段三**：赋能平台（模板库、Playbook、培训）+ 数据集成

## 8. 已确认的设计决策

- **合规规则来源**：Demo 阶段先用**行业通用规则**（RDPAC 公开准则 + 通用反商业贿赂/MLR 原则）做占位；护栏设计为可替换规则源，后续接入罗氏内部合规 SOP 时无需改动调用方。
- **交付形态**：待岗位要求（JD）明确后与用户共同决定（可运行 Web 原型 / 设计蓝图 / 知识库+对话助理最小闭环）。
