# 信息屋 Message House — 推广信息的组织方法

> 通用推广方法论。用于把一个产品的推广信息组织成"一个核心 + 若干支柱"的结构，保证一线传递一致、循证可溯。产品实例见各产品卡的「信息屋」段。

信息屋是把散落的卖点收敛成**一句核心信息 + 三条支持信息**的框架，像房子：屋顶是核心主张，立柱是循证支撑。

## 结构

| 层 | 作用 | 要求 |
|---|---|---|
| **屋顶：核心信息 Core Message** | 一句话回答"这个产品对目标患者的核心价值" | 单一、可记、不超适应症 |
| **立柱：支持信息 Supporting Messages** | 2~3 条支撑核心的循证论点 | 每条必带来源（说明书/指南/研究）+ 日期/版本 |
| **地基：证据 Evidence** | 支撑立柱的具体数据 | 承重数字标来源，PM 终核 |

## 编写原则

- **核心信息只有一个**：多个核心 = 没有核心。围绕目标患者/治疗线收敛。
- **每条支持信息可独立成立**：抽掉任一条，核心仍站得住；但三条合起来更有力。
- **循证前置**：先有证据再有主张，不是先有主张再找证据。数字必须能溯源到说明书或公开指南（见 [[roleplay-talk-tracks]] 的合规口径）。
- **一线可复述**：立柱语言要口语化、可在客户面前一句话讲完。

## 与合规的关系

- 核心/支持信息**不得超适应症**、不得夸大——所有主张回到产品卡的「获批适应症」与「核心循证」。
- 对外物料承载信息屋时须标 `⚠️ MLR 送审前草稿`。

## 应用场景

- 新产品上市：先定信息屋，再展开话术（[[roleplay-talk-tracks]]）、幻灯（[[AcademicSlideNarrative]]）。
- 竞品应对：核心信息是差异化锚点，异议应对（[[ObjectionHandling]]）是信息屋的防御面。
