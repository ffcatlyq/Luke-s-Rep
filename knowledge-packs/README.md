# 知识包（Knowledge Packs）

每个治疗领域一个知识包。知识包是**可插拔内容**——技能与任务流是通用的，切换治疗领域只需切换知识包。

## 现有知识包

| 知识包 | 状态 | 说明 |
|---|---|---|
| `hematology/` | ✅ Demo | 血液，6 个产品，兼作其他领域的模板 |
| `_shared/` | ✅ 共享 | 跨领域共享知识层（与 TA 无关），如 AI 工具目录。见 `_shared/README.md` |
| `_TEMPLATE/` | 📋 模板 | 新增领域从此复制 |

> `_shared/` 与治疗领域包**并列**，放跨 TA 通用、不该塞进某个领域包的知识。判据：换个治疗领域还成立 → `_shared/`；只对某 TA 成立 → 该 TA 包。

## 知识包标准结构

每个知识包遵循相同结构，技能层依赖此结构读取知识：

```
<therapeutic-area>/
├── pack.md              # 知识包元信息：领域概览、团队、产品清单、汇报线
├── landscape.md         # 疾病领域格局：疾病、患者旅程、诊疗路径、市场
├── franchise.md         # 产品组合逻辑：单品定位 + 组合协同
└── products/
    └── <product>/
        └── product.md   # 单产品知识：机制/适应症/循证/信息屋/竞品/定位/异议/合规边界
```

## 如何新增一个治疗领域（如眼科）

1. 复制 `_TEMPLATE/` 为 `ophthalmology/`
2. 填写 `pack.md`（团队、产品清单、汇报线）
3. 填写 `landscape.md` 和 `franchise.md`
4. 每个产品在 `products/<product>/product.md` 按模板填写
5. 完成——所有通用技能（双语汇报、竞品简报、讲者管理、物料+MLR）自动适用于新领域，**无需改动 `skills/` 或 `compliance/`**

> 关键：只要遵循标准结构，技能层就能无缝工作。这就是"通用引擎 + 可插拔知识包"的价值。
