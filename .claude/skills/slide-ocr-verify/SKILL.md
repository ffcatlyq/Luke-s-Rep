# slide-ocr-verify — 图片型幻灯/PDF的数字识别与验证

## 何时用这个skill

当承重数字**只以像素形式存在**——PPT/Slides导出的图片、扫描PDF、截图——
原生文本层为空，API（如Google Slides、PDF text）读不出数字。
此时必须"看图读数"，而看图读数**极易出错**（OCR会把9.61读成7.39、把两个数黏成40.937.4）。
本skill给出一套"读得准 + 验得住"的固定流程。

## 核心原则（来自实战血泪，模型无关）

1. **图里的数字 = 未经验证的证据**，不是可直接引用的事实。
2. **每个写入值必须有双重背书**：源页定位 + 独立算式/回读交叉验证。
3. **OCR一次不可信**：低分辨率一次性OCR必错，用"高DPI + 裁剪 + 放大"提纯。
4. **黏连是头号陷阱**：相邻单元格数字会连成一串（`40.937.4`），必须逐格裁剪。

## 标准流程（六步）

### 1. 渲染成高DPI图
不要用默认分辨率。承重数字页用300 DPI起步，读不清升600。
```bash
pdftoppm -f <页> -l <页> -png -r 300 input.pdf page
```
（Slides先export成PDF再渲染，见scripts/render_page.sh）

### 2. 定位 + 裁剪目标区块
按相对坐标裁出"只含目标数字"的小块，避免整页OCR的噪声与黏连。
```python
im.crop((int(w*x0), int(h*y0), int(w*x1), int(h*y1)))
```

### 3. 放大提纯（关键）
把裁剪块**等比放大到宽 ~1100–1200 px**，纵向可再拉伸1.6x让字符分离。
这一步决定OCR准确率。见scripts/crop_zoom.py。

### 4. OCR读数
```bash
tesseract v_block.png stdout --psm 6
```
`--psm 6`（单块统一文本）对表格块通常最好；数字列可试 `--psm 4/11`。

### 5. 交叉验证（不可跳过）
读出的数字必须用**独立第二路径**验证：
- **算式验证**：比值 = 分子 ÷ 分母；比例 = 分子 ÷ 分母。算出来对不上 → 读错了。
- **多次出现验证**：同一数字在源文档多处出现 → 三处都读，取一致值。
- **方法学例外**：CI若源自对数尺度合成，**不能**用点估计除法反推（会得到不同区间）。
 遇到CI优先读源印值，不硬算。

### 6. 回读确认
写入交付物后，重新渲染/读取写入位置，确认：
- 无双值黏连残留
- 写入值 = 验证值
- 未误伤相邻的已有正确值

## 输出纪律

- 每个AI读入/写入的数字用**醒目标注**（如紫色）便于人工复核。
- 留"方法学留痕"：说明该值来自"图片OCR + 算式/回读双重验证"，附源页。
- 无法验证的值标 `[来源待确认]`，**绝不**用"看似合理"的数字填空。

## 合规挂钩（罗氏 PM 场景）

本 skill 只负责"把图里的数字读准"，但读出的数字一旦进入**对外/一线物料**（幻灯、话术、detail aid），
须继续走本仓合规护栏（`compliance/guardrails.md`）：
- **疗效/安全性数字**：标注来源研究 `[来源：<研究名>]`，比对产品知识包 `product.md` 的获批适应症，不得 off-label。
- **物料草稿**：顶部标 `⚠️ MLR 送审前草稿`。
- **OCR 读数即"待核实证据"**：即便双重验证通过，写入对外物料前仍以说明书/已发表原文为准（见 `knowledge-packs/` 各 product.md 的"⚠️ PM 须核实"提示）。

## 反模式（禁止）

- 整页低分辨率一次性OCR后直接引用数字
- 相信单次OCR结果不做第二路径验证
- 用点估计除法反推本应是对数尺度合成的CI
- 凭记忆补一个"合理"的数字代替读不清的值
