# 图片型数字识别 —— 常见陷阱

> 从实战提炼的通用陷阱，每一条都是"为什么必须交叉验证"的证据。
> 示例数字为构造，仅用于说明陷阱形态。

## 1. 单值误读：小数字符连环认错

- **场景**：某数值型结果，图片型页面，分辨率偏低。
- **错误**：OCR把 `9.61` 读成 `7.39`（9→7、6→3、1→9连环误读）。
- **后果**：下游用它计算的比值全部跟着错。
- **修正**：高DPI（600）裁剪放大重读；该值在同文档多处出现，取一致值确认。
- **教训**：承重数字必须多处/高清确认，单次OCR不可信。

## 2. 黏连：相邻单元格连成一串

- **场景**：相邻单元格 `40.9` 和 `37.4` 被OCR连成一串 `40.937.4`。
- **后果**：得到一个不存在的数 `40.937`，若不察会直接写入。
- **修正**：逐格裁剪，每个单元格单独OCR。
- **教训**：整表OCR必产生黏连，必须按格裁剪（crop_zoom的意义）。

## 3. 多行单元格：误取错行

- **场景**：结果表每格有多行数值，来源/口径不同。
- **错误**：把多行黏在一起，或误取了不该用的那一行。
- **修正**：逐格逐行裁剪确认；写入后回读，核对无黏连残留、取值行正确。
- **教训**：写入后必须回读，确认无黏连、未误取错行。

## 4. 置信区间反推陷阱：除法 ≠ 对数尺度合成

- **场景**：某比值的置信区间。
- **错误**：想用点估计的分子/分母各自区间做除法反推CI，得到一个区间。
- **真值**：源印CI是对数尺度标准误合成的，与除法结果不符。
- **修正**：CI优先读源印值，不用点估计硬算。
- **教训**：**方法学要点** —— 比值的CI通常来自对数尺度标准误合成，
 不能用点估计除法反推。这是统计判断，不是OCR问题。

## 5. 只读文本层：漏掉图片里的内容

- **场景**：一批文件中部分是图片型，之前只读了文本层，且有截断。
- **后果**：基于不完整信息判断，结论失真。
- **修正**：所有文件连同渲染图片一起重读，重建判断。
- **教训**：有图片的源，"读了文本"≠"读全了"；必须连图一起读。

## 通用检查清单（写入任何图里数字前）

- [ ] 该页已300dpi+渲染，目标块已裁剪放大
- [ ] 数字经第二路径验证（算式 / 多处出现）
- [ ] CI未用除法反推（若源为对数尺度合成）
- [ ] 写入后已回读，无黏连、无错行、未误伤相邻正确值
- [ ] 每个值有源页 + 验证方式的留痕
- [ ] 无法验证的值标 `[来源待确认]`，未凭记忆填空

## 适用数据范围

本skill用于**已发表/聚合层面**的数值核对（如公开文献、报告里的汇总统计量）。
不用于患者个体数据，不处理未脱敏的PII/HCP信息。
