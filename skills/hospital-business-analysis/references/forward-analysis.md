# 正向分析路径 — 从真实 patient flow / 科室 profile 推到业务结果

> 五步法有**两个入口**，方向相反、互为补充：
> - **反向（结果倒推）**：从品牌份额/达成 gap 出发，漏斗式往上游找漏点。见 `workflows.md` 场景1。**已知结果、想找原因**时用。
> - **正向（本文件）**：从医院**整体 patient flow + 科室 profile** 出发，一步步往下推到业务结果。**做深度单院经营、要摸清全貌**时用。
>
> 深度单院分析（尤其重点院/一院一策）应以**正向为主**：先把真实分母和患者流构成搞清楚，再谈结果和 gap——否则拿着不准的分母算份额，全是空中楼阁。
> 来源：东区一院一策闭门会「五步法拆分逻辑」（2026-07，脱敏后沉淀）。

## 为什么要正向

反向倒推的隐患：**它默认现有数字是对的**。但真实医院里，分母本身常常是错的——外院送检混入、检出未导入、外院带方案倒挂、IPI 未记录……分母错，后面每一步的率都失真。

正向路径强制你**先建真实分母，再算率**：从"这家医院的患者到底从哪来、经过哪些科室、被谁处方"重建整条流，业务结果是这条流的自然产出，不是起点。

```
反向：份额低 → 哪步漏 → 为什么 →（常踩坑：分母本身是错的）
正向：真实 patient flow / 科室 profile → 纯化分母 → 分层 → 拆到人 → 逐步得出各步率 → 定位问题
```

## 正向 5 核心问（骨架）

深度单院分析按此顺序推进。每一问都是下一问的分母。

### 问 1｜分母准不准？—— 收治患者这个分母的准确性

一切的起点。分母不准，全盘皆错。

- **数据必须真实**：警惕"拍脑袋"的整数（如"60 vs 50 太精准了，是拍的还是真的？"）。数据要清楚、真实、全面。
- **横纵向比对**："70% 转化率"配上"每月只 5–6 个患者"就不可信——用绝对数反查率是否成立。
- 拿不到的标 **"待补"**，不硬算（对齐 `pre-analysis-inquiry.md` 数字层）。

### 问 2｜分母怎么分？—— 初治 vs 复发，初治再细分 IPI

把总分母拆成临床分层：

- 初治多少 / 复发多少？
- 初治里 **IPI 0-1 / 2 / 3-5** 各多少？（IPI 常未系统记录 → 标"待补"，先定数据从哪来）
- 复发里线数、亚型构成？
- **瘤种分开建表**：一家院若有多个瘤种/部位（如 DLBCL 与中枢 PCNSL），**各建一张表分别走五步**，别混。

### 问 3｜分母拆到谁？—— 落到具体客户（带组主任）

无论初治还是复发，**拆到具体处方人**——不看科室平均：

- 每个带组主任手里各分层各多少患者？
- ⚠️ 关键人群**不会都在一个主任手里**，必须逐人拆。
- 拆到人才能做问 4 的处方动机分析。

### 问 4｜转化率多少？—— 初治转化率 / 复发转化率

有了纯化、分层、拆到人的分母，才算真实转化率：

- 各分层、各客户的真实转化率是多少？
- ⭐**客户的处方动机 = 真实需求的体现**：为什么转、为什么不转，就是驱动/阻碍因素。
- 深化诊断（分层×关键处方人二维矩阵、处方动机三分类、行为矛盾优先、关键组优先）见 `conversion-diagnosis.md`；产品特定口径见 `knowledge-packs/hematology/playbooks/`。

### 问 5｜DOT 真不真？—— 已转化患者的真实足剂量/足疗程

最后看已转化患者用够没有：

- 真实 DOT vs 标准足量的 gap 是多少？
- gap 归类：是**足剂量**问题还是**足疗程**问题？（两者不同）
- gap 在哪些人群（初/复发、IPI、某高危因素）、哪些医生？
- gap 原因：疾病进展 / 患者管理不到位 / AE 处理不到位 / 流失到其他医院？
- 这些医生的观念是什么、资源覆盖是什么、缺什么？

> ⚠️ DOT 的"超标"也要查：若真实 DOT 高于标准足量（如标准 21 支却用了 29 支），要问为什么——可能提示方案理解偏差或数据口径问题，同样是待厘清的信号。

## 科室 profile：正向分析的地基

正向路径的前提是摸清科室 profile——**这家院的患者到底怎么流进来**：

- **血液科自身**：床位数、周转、收治能力、主任/带组主任构成。
- **上游科室**：病理科（检出能力、有无淋巴瘤专人）、外科各科（胃肠/眼科/耳鼻喉/呼吸/心内等——不典型患者散落处）。
- **竞争科室**：肿瘤科（DLBCL 可能被分流去肿瘤科）。
- **多院区**：总院 vs 分院/北院——分院常是"未开发的自留地"，profile 和打法完全不同。
- **患者来源**：本院检出 vs 外院带诊断/方案而来（影响分母口径，见问1）。

> 拆到最细：某外科主任叫什么、专门送病理的护士是谁、病理科能检出该瘤种的医生是谁——从病理科 raw data 反查，才能定位可干预的具体人和环节。个人信息脱敏、不进 git。

## 行动：难易 × 潜力 排序 + 分工

摸清问题后出行动，两条纪律：

### 排序：潜力大且容易的先做

找到阻碍后按 **改变成本 × 覆盖目标患者数** 排序，**潜力大且容易的先做掉**。典型难度阶梯（由易到难）：

```
梳理患者情况（最易）→ 追转化 → 缩短住院时间 → 借床/开日间（最难，涉科室协调）
```

### 分工：难度决定谁来做

| 难度 | 谁来做 | 例 |
|---|---|---|
| 容易 | 代表 | 梳理患者情况、追转化 |
| 中等 | 跨部门协调 | 缩短住院时间、日间门诊 |
| 难（客情/利益分配）| **圈长（LEL）** | 借床、科室关系突破、构建利益共同体 |

> 核心：**容易的让代表做，难的协调跨部门，最难的客情/利益协调由圈长做**。别让代表去啃圈长该啃的骨头，也别让圈长陷在代表能做的琐事里。

## 正向路径与反向漏斗怎么合

- **深度单院/一院一策**：正向为主（先建真实分母全貌）→ 得出各步率后，用反向漏斗的**留存率/Driver Tree 弹性**定位最大漏点 → 接 `workflows.md` 场景2/3 归因、出动作。
- **快速体检/已有干净数据**：反向为主，直接漏斗诊断。
- 两者**共用**同一套三层透镜（`pre-analysis-inquiry.md`）、TOC 聚焦、解法库。

## 预警用法

有了真实数据 + 对区域的认知，五步法就能当**预警系统**：一旦某步指标异动，立刻定位问题出在哪一步、哪类人群、哪个医生，给出对应计划。**数据是第一位的——必须清楚、真实、全面。**

## 定位（人群）

正向深度分析主要服务**销售管理（LEL/圈长）**做重点院一院一策。表格不是为了上级管理 LEL，而是 **LEL 自己摸清每家院、做精细化运营**的工具。

## 合规

单院/患者/医生数据属**敏感级**：脱敏、不外传、不进 git。方案/DOT 表述以说明书为准、不超适应症。**合理临床选择不算阻碍**——不得为冲率推动不适宜患者（见 `conversion-diagnosis.md`）。
