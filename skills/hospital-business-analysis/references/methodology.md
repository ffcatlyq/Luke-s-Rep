# 方法论 — 五步法主干 + 五层外部方法论

> 主干是洪晓老板的**五步患者流漏斗**（领域知识，见 `five-step-funnel.md`）。本文件说明如何外挂五层成熟方法论，把领域直觉升级成**可量化、可聚焦、可归因、可固化**的分析引擎。融合原则：**主干不动，外框补能力，不堆砌**。
>
> **两个分析方向**：反向（结果倒推找漏点，见 `workflows.md` 场景1）与正向（真实 patient flow/科室 profile 推到结果，见 `forward-analysis.md`）。深度单院以正向为主、反向定位漏点，二者共用下述所有方法层。

## 融合骨架一图

```
  单院 × 全产品  =  关键客户账户视角（KAM 外框）
  ┌─────────────────────────────────────────────┐
  │  五步患者流漏斗（主干·领域）                  │
  │    步1早筛 → 步2诊断 → 步3收治 → 步4方案 → 步5周期 │
  ├─────────────────────────────────────────────┤
  │  量化层  Driver Tree × Cascade of Care  → 每步漏多少 │
  │  聚焦层  TOC 五步聚焦（循环）            → 先解哪个   │
  │  归因层  5 Whys / 鱼骨图                 → 为什么漏   │
  │  动作层  MDT / 排床 / 专人（原实战解法） → 怎么堵     │
  │  固化层  DMAIC 的 Control + 复盘节奏     → 不反弹     │
  └─────────────────────────────────────────────┘
```

## 层 1｜量化层：Driver Tree × Cascade of Care

**解决五步法的短板**：漏斗是定性的，"卡在哪步"靠感觉。量化层给它算式。

### Driver Tree（患者数驱动树）——把漏斗变乘法

单院业务量可拆成一条乘法链：

```
业务量 = 合格患者池 × 诊断率 × 导入率 × 轮转率 × 转化率 × DOT系数
         (步1前端)  (步1)   (步2)   (步3)   (步4)    (步5)
```

- 每个因子对应漏斗一步；**哪个因子最低 = 最大漏点**。
- 用**弹性排序**：算"某因子提升 10% 带来的业务增量"，增量最大的就是优先撬动点。
- 目标（如优罗华>70%）落到某个因子上，就有了算式支撑，不再是空口号。

### Cascade of Care（诊疗连续性级联）——给漏斗标准留存率

公卫成熟框架（HBV/HCV/HIV/糖尿病标准工具，如 HBV 全球级联 PMID 37517414；感染病 care cascade 最佳实践 PMID 38049823），**淋巴瘤领域尚少系统应用**——把它迁移过来，既标准化又是创新。

- 每步算**留存率 = 本步进入数 / 上一步数**，画成阶梯瀑布图。
- 与 Driver Tree 互补：Driver Tree 是"乘法预测"，Cascade 是"留存诊断"，同一组因子两种读法。
- 好处：分析结果**可对标、可复盘、可发表**（学术上站得住，利于 KOL 沟通）。

> 数字口径参考知识包 `customers/segmentation.md`（患者细分维度）与 `wiki/concepts/PatientJourney.md`（诊疗节点）。

## 层 2｜聚焦层：TOC 五步聚焦（约束理论）

**这是五步法"一次解一个问题"的理论原型**（Goldratt《目标》）。TOC 本身也是五步，且**闭环**——正好补上五步法缺的"解完回头"：

| TOC 步 | 对应本 skill 动作 |
|---|---|
| 1 识别约束（Identify） | 用量化层找出留存率/因子最低的那一步 = 瓶颈 |
| 2 挖尽约束（Exploit） | 不花大钱，先把现有资源在瓶颈上用到极致（如优化排床流程）|
| 3 迁就约束（Subordinate） | 其他环节配合瓶颈节奏，不制造无效繁忙 |
| 4 提升约束（Elevate） | 必要时投入资源扩容瓶颈（如建日间病房、设专人）|
| 5 回到第一步（Repeat） | 瓶颈解除后，回步骤 1 找下一个约束——**持续增长的引擎** |

**关键洞察**：五步法的"一次聚焦一个主要问题"= TOC 的"任何时候只有一个约束值得攻"。别贪多，堵一个、松一个、再找下一个。

## 层 3｜归因层：5 Whys / 鱼骨图

**解决五步法的短板**：漏斗告诉你"卡在哪步（WHERE）"，但不告诉你"为什么（WHY）"。不追根因，动作就会打偏。

- **5 Whys**：对最大漏点连问五个为什么，直到触及可干预的根因。
  - 例：转化率低 → 为何？没选 1L 优 → 为何？医生观念滞后 → 为何？缺规范复盘 → 为何？没有定期诊断复盘会 →**根因：缺 MDT 机制**（可干预）。
- **鱼骨图（Ishikawa）**：漏点原因按 人/流程/科室/政策(DRG)/竞争 分类，避免只盯一个方向。
- 现有实战解法（MDT/排床/专人）本质就是"根因→动作"的产物，本层把它显性化。

## 层 4｜动作层：实战解法（原五步法 P3）

根因确定后出动作。解法库见 `five-step-funnel.md` 末尾表。动作要 **SMART**：谁、做什么、何时、用什么指标衡量。

## 层 5｜固化层：DMAIC 的 Control + 复盘节奏

**解决五步法的短板**：一次性分析容易"分析完就完了"，漏点会反弹。

- DMAIC = Define-Measure-Analyze-Improve-**Control**，本 skill 的场景 1-3 对应 DMA-I，**场景 4 就是 Control**。
- 给堵漏动作配**监控指标 + 复盘节奏**（如月度回疗间隔、季度留存率），纳入 `business-review` 例会跟踪。
- 堵住了不放手，直到稳定，再回 TOC 步 5 找下一个。

## 外框｜KAM 关键客户账户视角

"单院 × 全产品"本质是**把一家重点医院当关键客户做账户计划**：

- 一院一档：漏斗现状 + 主攻漏点 + 动作 + 责任人 + 复盘节奏。
- 与 `customer-segmentation` 的医院分级（C30/T70/T300）交叉——高级别医院优先做深度单院分析。

## 什么时候用哪层（别全上）

| 场景 | 至少用 | 可选加 |
|---|---|---|
| 快速诊断一家医院卡哪 | 主干漏斗 + Cascade 留存率 | Driver Tree 弹性排序 |
| 定先解哪个漏点 | TOC 聚焦 | Driver Tree 增量测算 |
| 想清楚为什么漏 | 5 Whys | 鱼骨图（原因多维时）|
| 让改进不反弹 | DMAIC Control + 复盘 | 纳入 business-review |
| 管理多家重点院 | KAM 一院一档 | customer-segmentation 分级 |

> Occam's razor：能用主干 + 一两层解决就不叠全套。方法论是为把漏点说清、把动作对准，不是为显得全面。
