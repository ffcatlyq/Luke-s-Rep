# 工作流 — 4 个场景逐步流程

> 每个场景给：触发、输入、步骤、产出。全程守合规（单院数据敏感、不外传、方案表述以说明书为准）。
> 四场景合起来是一个闭环：诊断 → 归因 → 动作 → 循环（对应 DMAIC 与 TOC 循环）。

---

## 场景 1｜单院漏斗诊断

**触发**："分析这家医院""它卡在哪一步""帮我看看 XX 医院的业务"
**输入**：医院名、各产品业务数据（患者数/份额/DOT 等）、医院分级（C30/T70/T300）

> **两个方向选一个**（详见 `forward-analysis.md`）：
> - **反向**（本场景默认）：已有较干净数据、想快速找漏点 → 直接建漏斗、算留存。
> - **正向**：深度单院/一院一策/重点院、要先摸清真实分母全貌 → 先走 `forward-analysis.md` 的 5 核心问（分母准确性→分层→拆到人→转化率→DOT）建真实 patient flow，再回本场景第 3 步用留存率/弹性定位最大漏点。

**步骤**：
0. **分析前质询（给结论前必做，三层透镜见 `references/pre-analysis-inquiry.md`）**：
   - **数字层**：口径自洽 / 突变异常 / 沉默证据（谁不在数据里）；缺失标"待补"，不臆测硬算。
   - **归因层**：痛点错位 / 内部分流 vs 外流 / 结构（够不着）vs 观念（不信）/ 一因多果 / 时序巧合。
   - **人与局层**：⭐行为矛盾优先（认可却不用、准入却不可及、最会用却在丢）/ 角色杠杆错配 / 政策外部手（DRG/停限控）。
   - **收束**：只把会改变结论的疑点转成 1–2 个反问（正文编号选项）；信息够就直接分析，别反复追问。
1. **确认口径**：先问清有哪些数据（诊断数、收治数、各产品治疗数、回疗间隔等）；缺的标"待补"，不臆造。
2. **建五步漏斗**：把数据填进患者流五步（早筛→诊断→收治→方案→周期），用 `templates/single-hospital-worksheet.md`。
3. **算留存率（Cascade）**：每步 = 本步数 / 上一步数，画阶梯，看哪步掉得最狠。
4. **算 Driver Tree（可选）**：业务量 = 池 × 诊断率 × 导入率 × 轮转率 × 转化率 × DOT系数；对每个因子做 +10% 弹性测算，排序撬动潜力。
5. **分品牌 gap**：每个产品对自己业务目标（从知识包读）查差多少，落在哪步。
6. **定位最大漏点**：留存率最低 + 弹性最大的那一步 = 主攻候选。
7. 产出**单院漏斗诊断卡**（现状 + 各步留存 + 分品牌 gap + 初判最大漏点）。

**产出**：填好的单院分析工作表 + 一句话结论"这家医院主要卡在第 X 步"。

## 场景 2｜根因与聚焦

**触发**："为什么漏""该先解决哪个""是不是床位问题"
**输入**：场景 1 的诊断卡

**步骤**：
0. **痛点复核**：再确认场景 1 定位的"最大漏点"确实是数据支撑的真痛点，而非提问者的先入判断——若提问者一开始问的方向与数据不符，此处显性纠偏，别顺着伪痛点往下追根因。
1. **全品牌解题视角**：确认这个漏点是否同时卡住多个产品（共性漏点优先于单品漏点）。
2. **TOC 锁定单一约束**：若有多个候选漏点，只选一个——用 Driver Tree 增量或"解一个能带动几个产品"判断。
3. **5 Whys 追根因**：对选定漏点连问为什么，直到触及可干预根因（人/流程/科室/DRG/竞争）。
4. **鱼骨图（原因多维时）**：把根因按类别铺开，避免只盯一个方向。
5. 产出**根因聚焦卡**：一个主攻漏点 + 一条根因链 + 归入哪个类别。

**产出**：明确"先解哪个、为什么漏"，交接场景 3。

> ⚠️ 别贪多。TOC 原则：任何时候只有一个约束值得攻。

## 场景 3｜堵漏动作计划

**触发**："怎么堵""出个增长计划""该做什么动作"
**输入**：场景 2 的根因聚焦卡

**步骤**：
1. **选动作**：从解法库（`five-step-funnel.md` 末表）按根因选（MDT/取材标准/绿通/排床/日间/专人/回疗引导等）。
2. **SMART 化**：每个动作定 谁、做什么、何时、衡量指标。
3. **定监控指标（DMAIC Control）**：给主攻漏点定 1-2 个跟踪指标（如回疗间隔、留存率）+ 复盘节奏。
4. **接例会**：把指标与复盘纳入 `business-review` 月度/季度跟踪。
5. **风险与依赖**：标出需要跨部门/上级支持的项（如政策解限、日间病房建设）。
6. 产出**单院增长计划**。

**产出**：可执行的一院一档增长计划（动作 + 责任人 + 指标 + 节奏）。

> ⚠️ 涉及治疗方案/周期规范的沟通内容，须以说明书为准、不超适应症；对外物料经 MLR。

## 场景 4｜循环推进（TOC 循环 / DMAIC Control）

**触发**："上次那个解决得怎样""下一步该看哪""复盘一下"
**输入**：上一轮增长计划 + 最新数据

**步骤**：
1. **复盘堵漏效果**：对比动作前后的漏点指标，判断是否稳定解除。
2. **判断是否收口**：稳定 → 进入 Control 维持；未稳定 → 回场景 3 调动作。
3. **回步骤 1 找下一个约束**（TOC 第五步）：瓶颈解除后，重跑漏斗诊断，锁定下一个最大漏点。
4. **更新一院一档**：记录本轮结论、下一轮主攻点。
5. 产出**单院复盘 + 下一轮聚焦**。

**产出**：持续增长的循环——一家医院不是分析一次，而是"堵一个→松一个→找下一个"。

## LEL 带教用法（人群提示）

LEL/圈长可把本流程当**团队教练脚本**：带一线用同一套漏斗语言复盘辖区医院，让"卡在哪步"成为团队共同话术。个案数据在内部场合讨论，脱敏、不外传。
