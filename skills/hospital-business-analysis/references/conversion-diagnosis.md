# 转化率诊断法 — 分层 × 关键处方人二维拆解

> 五步法**步 4「治疗方案」**的深化方法。转化率是所有步里**最需要"分品牌 + 拆到人"**的一步——因为"选不选某方案"是**具体医生的处方决策**，不是科室平均值能解释的。
> 这是**通用方法（TA 无关）**：任何产品、任何瘤种做转化率诊断都套这套流程。产品特定的分层口径、关键人群优先级、处方动机实例，放 `knowledge-packs/<TA>/playbooks/<product>-conversion.md`。

## 核心原则：先梳现状，再谈提升

⚠️ **不要一上来就开药方。** 想提升转化率，第一步永远是**梳理 patient flow 现状、量化真实转化率、锁定卡在哪、卡在谁手里**——现状不清就给方案，必然修错地方。

诊断链路（照序做，不跳步）：

```
梳 patient flow 现状 → 拆分层 × 关键处方人 → 算各格真实转化率
   → 锁关键人群/关键人 → 归因到处方动机(三分类) → 排杠杆 → 出方案
```

## 第 1 步：梳 patient flow，先防"分母失真"

转化率 = **用目标方案的患者数 ÷ 接受治疗的目标患者数**。分母脏，后面再细也白搭。三条纪律：

1. **只诊断步 4「选没选」**。把三类漏点**分开统计、不混进转化率**：
   - 没收进来治疗 = **步 3 收治**，不是转化；
   - 用了但没用够周期/支数 = **步 5 DOT**，不是转化；
   - 选没选对方案 = **步 4 转化**（本方法只管这个）。
2. **分母只算"目标人群"**：按产品适应症圈定（如某线数/某瘤种），圈错分母，转化率无意义。
3. **拿不到的数标"待补"，不硬算**（对齐 `pre-analysis-inquiry.md` 数字层·沉默证据）。

## 第 2 步：二维拆解 —— 临床分层 × 关键处方人

科室平均转化率会**掩盖真相**。必须拆成一张二维矩阵：

|  | 关键处方人 A | 处方人 B | 处方人 C | … |
|---|---|---|---|---|
| **分层 1（关键人群）** | 转化率? | | | |
| **分层 2** | | | | |
| **分层 3** | | | | |

- **纵轴·临床分层**：按该产品**临床上真正影响处方决策的维度**分层（如预后评分、线数、亚型、体能）。分层维度从产品 playbook 读，不通用硬编码。
- **横轴·关键处方人**：拆到**带组主任/关键处方医生**个人，不看科室平均。"关键人在谁手里、每个人转化多少"才是可行动的。
  > ⚠️ 只用**聚合诊疗流数据**，个人处方行为分析**不落患者可识别信息**；医生个人信息属敏感级，产出脱敏、不进 git。

**为什么要二维**：转化率低可能是①某个关键人群整体没打透（纵向问题）、也可能是②某几个主任不用（横向问题）。一维看不出是哪种。

## 第 3 步：锁关键人群 —— 先打关键组，别撒胡椒面

分层算完，**先看关键人群（高价值/高证据/大分母那组）是否达标**：

- 关键组**没到目标水平** → 资源全压这组，其余组后置；
- 判断"该先打哪组"用 **证据强度 × 分母大小 × 达成 gap**，不是哪组低打哪组。
- ✅ 明确写清"为什么后置某组"——通常是**该组循证相对有限 / 分母小 / 优先级理应在关键组之后**，而非"不能用"。

> 目标水平（如关键组该到 80–90%）从产品 playbook / franchise 业务目标读，不在本文件硬编码。

## 第 4 步：归因到处方动机 —— 三分类（决定用什么杠杆）

对每个"没转化"的处方人，把阻碍归到**三类**——**这一步决定杠杆，混类必用错药**：

| 阻碍类型 | 本质 | 典型信号 | 杠杆 | 成本 |
|---|---|---|---|---|
| **观念**（不信 / 不知） | 认知缺口 | 误解适应症/循证、怕某不良反应、定位混淆 | 循证沟通 + 纠正认知 | 低（优先打）|
| **结构**（够不着） | 外部约束 | DRG/药占比、支付能力、准入未上架、排床 | 支付/流程/准入沟通 | 高（慢工）|
| **合理临床选择** | 医学判断 | 患者确不适合（禁忌/高风险/更优替代）| ⚠️**不是阻碍，别硬转** | — |

⭐ **第三类最容易被忽略，必须主动剔除**：为冲转化率去推不该推的患者，是**合规 + 医学伦理红线**。它不算漏点、不进"待改进"清单。

## 第 5 步：⭐行为矛盾优先 —— 找最强信号

别只盯"转化率低的人"（可能只是他病人结构不同，是合理临床选择）。杠杆最大的是**行为矛盾**（对齐 `pre-analysis-inquiry.md` 人与局层⭐）：

- **认可某方案却不用** → 信号最强，直接问卡在哪（多半是隐藏的结构障碍）；
- **最会用却在丢患者** → 有隐藏漏点（可能漏到步3/步5）；
- **有准入却不可及** → 政策/流程外部手（如已准入未上架的窗口期）。

## 第 6 步：排杠杆 + 出方案（TOC 一次一个）

- 阻碍按 **改变成本 × 覆盖目标患者数** 排序：**观念类（免费增量）先打 → 结构类后置**。
- 关键人同理：集中打"**目标患者多 × 转化率低 × 阻碍可改变**"的那几个，不撒胡椒面。
- **TOC 一次只主攻一个**（对齐 `methodology.md`）。方案落地后定指标、定复盘节奏，回步骤 1 找下一个。

```
【分母纯化自检】

□ 不可得数据已标"待补"

【二维矩阵】临床分层 × 关键处方人 → 各格真实转化率（数据脱敏）

【处方动机归因】每个"没转化"的处方人 → 观念 / 结构 / 合理临床(剔除)

【杠杆排序】按 成本×患者数 → 主攻一个：______   指标：______  复盘节奏：______
```

## 与其他方法的接口

- 上游现状/分母 → `five-step-funnel.md` 步4；数字质询 → `pre-analysis-inquiry.md`
- 根因 5 Whys / TOC 聚焦 → `methodology.md`
- 旅程对照找机会点 → `patient-journey-mapping.md`
- **产品特定打法（分层口径、关键人群优先、动机实例）→ `knowledge-packs/hematology/playbooks/<product>-conversion.md`**
- 达成 gap 归因 → `performance-review`；分层数据/透视 → `data-analysis`

## 合规

- 医生个人处方行为、单院患者数、客户信息属**敏感级**：脱敏、不外传、不进 git。
- 方案规范性表述**以说明书为准、不超适应症**；对外须经 MLR。
- **合理临床选择不算阻碍**——不得为冲转化率推动不适宜患者。
