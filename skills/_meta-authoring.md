# 元技能：把任务沉淀成 skill（Authoring Skills）

> 这是"如何写/优化 skill"的 SOP。skill 是干活的标准流程——每次任务后沉淀一次，下次更快更稳。
> 属**通用引擎**，跨治疗领域复用。

## 何时触发
- 每完成一项**有流程、可能重复**的任务后，主动问用户是否沉淀成 skill。
- 用户说"把这个流程做成 skill / 固化下来 / 存成 SOP"。

## 先判断：新建 vs 优化 vs 不做

| 情况 | 处理 |
|---|---|
| 已有 skill 覆盖，只是细节不同 | **优化**已有 skill（补步骤/补检查项） |
| 全新的、会重复的流程 | **新建** skill |
| 一次性、不会重复、无质量步骤 | **不做**——别为"显得规范"造无用 skill |

> 判断标准：**会重复 + 有可复用流程 + 有质量要求**，三者具备才值得成 skill。

## 新建 skill 的步骤

1. **命名**：`skills/<动词-名词>.md`（如 `competitive-brief.md`），能一眼看出干什么。
2. **按标准结构写**（与现有技能一致）：
   - **触发条件**：什么诉求/触发语会用到它
   - **输入**：需要哪些信息；缺失则追问
   - **任务流**：编号步骤，含"先读知识包""挂合规护栏""沉淀 outputs"
   - **产出模板**：可直接套用的结构（表格/清单/成稿）
   - **合规检查**：本技能强制的自查项
3. **不硬编码产品知识**：运行时从 `knowledge-packs/<领域>/` 读，保证跨领域通用。
4. **登记**：在 `skills/README.md` 的技能表加一行。
5. **验证**：跑一次真实场景，确认技能被正确触发、产出符合模板。

## 优化已有 skill

- 把本次踩的坑/新增的质量步骤补进对应 skill 的"任务流"或"合规检查"。
- 反馈驱动：用户指出的"哪步错了/漏了"直接固化为检查项，避免重犯。
- 保持结构不变，只增量改进。

## 写好 skill 的原则
- **精简可执行**：步骤是给运行时照做的，不写空话；一条步骤 = 一个可检查动作。
- **验收写进流程**：把"怎么算合格"做成 skill 里的检查清单。
- **单一职责**：一个 skill 干一类事；跨多类拆成多个。
- **通用优先**：能跨治疗领域就不绑定具体产品。

## 沉淀话术（任务后主动问）
> 这次流程要沉淀成 skill 吗？我看它 [会重复 / 有可复用步骤]，建议 [新建 `xxx.md` / 优化已有 `yyy.md`]。要我做吗？
