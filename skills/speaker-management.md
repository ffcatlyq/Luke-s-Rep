# 技能：讲者管理 + 合规（Speaker Management）

> 角色：**赋能 + 合规**。JD 单列职责"develop speaker management system and maintain operation excellence"。血液领域学术活动密集，此为**高合规敏感**技能，深度绑定护栏。

## 触发条件
用户诉求包含："讲者遴选""speaker""场次分配""讲者库""学术会讲者""讲者合规"等。

## 输入（缺失则追问）
- 场景（建立讲者体系 / 单次会议遴选 / 场次分配 / 合规自查）
- 产品/疾病领域与学术主题
- 候选讲者信息（资质、既往合作）——注意不采集与销量相关信息
- 会议规模、场次数、预算范围（如适用）

## 任务流
1. **明确合规前提**（先行声明红线）：
   - 遴选**只看学术资质与专业贡献**，与处方量/采购量无关。
   - 劳务符合**公允市场价值（FMV）**，有标准、合同、交付证明。
   - 单一讲者**年度场次/金额上限**并留痕。
   - **利益冲突**申报与规避。
2. **建立/应用遴选标准**：学术职称、专业领域匹配、学术产出、演讲能力、既往合规记录。
3. **讲者库结构**：给出字段化讲者库模板（不含销量类字段）。
4. **场次分配**：按学术匹配度与合规上限分配，输出分配表。
5. **内容合规**：讲者内容须基于循证、不得 off-label、不得夸大（引用相关 `product.md`）。
6. **运营看板**：给出可跟踪的运营指标（场次、覆盖、合规留痕状态）。
7. **合规自查**：附讲者管理合规自查清单。
8. **沉淀**：存 `outputs/speakers/<日期>_<主题>_讲者方案.md`。

```markdown

> ⚠️ 遴选与劳务须符合合规要求，本方案为草案，须经合规确认

## 1. 遴选标准（与销量无关）
| 标准 | 权重 | 说明 |
|---|---|---|

## 2. 讲者库 / 候选清单
| 讲者 | 单位/职称 | 学术领域 | 匹配度 | 年度已有场次 | 利益冲突申报 |
|---|---|---|---|---|---|
（⚠️ 不含处方/采购相关字段）

## 3. 场次分配
| 场次/主题 | 拟定讲者 | 学术匹配理由 | 是否触及年度上限 |
|---|---|---|---|

## 4. 讲者内容合规要点
- 基于 <product.md> 已获批适应症与循证；不得 off-label/夸大

## 5. 运营看板指标
- 覆盖率 / 场次分布 / FMV 合规率 / 留痕完整度

## 6. 合规自查清单
（见下）
```

## 合规自查清单（本技能，强制）
- [ ] 遴选标准与处方/采购量**无任何关联**
- [ ] 劳务费符合 FMV，有标准与凭证
- [ ] 单一讲者年度场次/金额未超上限，已留痕
- [ ] 利益冲突已申报与规避
- [ ] 讲者内容基于循证、无 off-label、无夸大
- [ ] 所有安排可审计留痕
- [ ] 讲者库不含销量类字段

## 灰区处理
遴选理由若隐含商业考量 → 立即提示风险，改为纯学术标准，建议合规确认。
