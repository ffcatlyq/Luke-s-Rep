# Omnichannel Engagement — 场景工作流

## 场景 1：客户旅程设计

**输入**：目标客户分层（来自 `customer-segmentation`）、产品/活动目标。

**步骤**：
1. **定旅程阶段**：认知 → 兴趣 → 尝试 → 采用 → 忠诚（按实际调整，见 `methods.md`）。
2. **每阶段设目标**：这个阶段想让客户认知/相信/做什么。
3. **识别关键触点**：每阶段客户会在哪些场景接触信息。
4. **初配渠道**：每触点用面对面还是数字（按客户分层与阶段）。

**产出**：客户旅程地图（见 `templates/journey-map.md`）。

## 场景 2：触点-内容-渠道匹配

**输入**：旅程地图、可用内容资产。

**步骤**：
1. **列内容需求**：每阶段/每触点需要什么内容（学术、循证、教育、提醒）。
2. **匹配渠道**：按内容-渠道矩阵（见 `methods.md`）——深度学术走面对面，高频提醒走数字。
3. **标注内容状态**：现有 / 待开发；待开发的走 `promo-material-mlr` 起草并送审。
4. **一致性校验**：跨渠道核心信息一致，不矛盾。

**产出**：触点-内容-渠道计划（见 `templates/touchpoint-plan.md`）。

## 场景 3：跨渠道节奏编排

**输入**：触点计划、周期（月/季）。

**步骤**：
1. **排期**：把触点按时间铺进周期。
2. **节奏校验**：避免同一客户短期内触点过密（骚扰）或过疏（遗忘）；面对面与数字交替补位。
3. **联动设计**：数字触点为面对面预热/跟进（如会前推送、会后邮件）。
4. **留监测点**：每阶段设互动效果观测指标。

**产出**：跨渠道节奏排期（见 `templates/cadence-schedule.md`）。

> 所有对外内容须经 MLR（走 promo-material-mlr）；数字互动遵守 consent 与隐私。
