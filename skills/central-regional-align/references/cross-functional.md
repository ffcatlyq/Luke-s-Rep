# 横向：跨部门协作方法论

PM 作为品牌的商业负责人，日常要横向拉通多个职能。核心不是"多开会"，而是**让协作有结论、有主、可追踪**。

## PM 的跨部门协作地图

| 部门 | 对口角色 | 典型协作频率 | 典型协作场景 |
|------|---------|:---:|-------------|
| **Medical（医学部）** | CMM / MSM | 每周~每月 | 核心科学信息一致性、推广材料医学审核、学术活动共建 |
| **Market Access（准入）** | Access Lead | 每月 | 医保准入准备、价值证据需求、院内准入支持 |
| **销售（Sales）** | 销售管理/圈长 | 每周 | 策略落地、一线执行反馈、目标与资源对齐 |
| **PDMA / 注册** | Regulatory Lead | 按需 | 新适应症获批节奏、说明书更新、标签管理 |
| **财务（Finance）** | Business Partner | 每月~每季 | 预算规划、投入产出、费用合规 |
| **Commercial Excellence / CE** | CE / 数据 | 每季 | 数据分析支持、绩效追踪、CRM/工具 |
| **合规（Compliance）** | Medical/Legal Compliance | 按需 | MLR 审批、合规咨询、灰区裁定 |

> 本表为**框架参考**，具体对口与频率参考团队实际安排与内部 SOP。

## 协作模式（PM 居中拉通）

```
                    上级 / Franchise Head
                          │
                    ┌─────┴─────┐
                    │    PM     │ ← 品牌商业负责人（居中拉通）
                    └─────┬─────┘
        ┌────────┬────────┼────────┬────────┐
        │        │        │        │        │
     Medical  Access   Sales    PDMA    Finance/CE
        │        │        │        │        │
        └────────┴────────┼────────┴────────┘
                          │
                    区域市场 / 一线（纵向执行层）
```

> 横向拉通各职能，纵向对接区域执行——PM 是两个维度的交汇点。

## 会议效率原则

**会前**
- 提前 24h 发议程 + 预读材料
- 每个议题标注时间分配和期望产出（讨论 / 决策 / 信息同步）

**会中**
- 准时开始、准时结束
- 每个议题明确结论或下一步
- 实时记录行动项（责任人 + 截止日）
- 离题讨论进"停车场（Parking Lot）"，不占正题时间

**会后**
- 24h 内发纪要（走 `meeting-minutes`）
- 行动项录入追踪表
- 下次会前跟进未完成项

## 行动项闭环（协作最大杀伤是"定了没人追"）

1. **登记**：来源会议、责任人、截止日、状态。
2. **预警**：逾期项显式标注 + 建议行动。
3. **追踪**：下次例会开场先过未完成项。
4. **闭环**：完成/延期/取消都记录，延期写清原因与新期限。

## RACI 设计要点

| 字母 | 含义 | 要点 |
|---|---|---|
| **R** Responsible | 执行者 | 可多人 |
| **A** Accountable | 负责人 | **每任务有且仅有一个** |
| **C** Consulted | 被咨询 | 双向沟通，事前 |
| **I** Informed | 被知会 | 单向告知，事后 |

**校验规则**：无 A 的任务 = 没人负责；多 A 的任务 = 推诿温床。设计后逐行确认认领。

## 升级机制

跨部门遇阻时的升级路径：

```
Level 1：工作层直接沟通（PM ↔ 对口同事）
    ↓ 未解决
Level 2：双方 Line Manager 介入
    ↓ 未解决
Level 3：VP / Franchise Head 层协调
    ↓ 未解决
Level 4：GM / Country Head 决策
```

**升级原则**
- 先在工作层尝试，避免过早升级。
- 升级时提供：问题描述、已尝试的方案、期望的决策。
- 升级不是投诉，是寻求资源与决策支持。
- 升级后向对方通报结果，维护协作关系。

## 与其他技能衔接

- 跨部门**大项目**（有明确起止，需 WBS/风险/预算）→ `project-management`
- 会议纪要 → `meeting-minutes`
- 跨部门邮件 → `email-authoring`
- 对上/正式双语呈现 → `bilingual-report`

## 合规

- 跨部门共享的物料须已过 MLR 或标 `⚠️ MLR 送审前草稿`。
- 共享的客户/销售数据脱敏、聚焦趋势，不外传 PII、不进 git。
- 协作中的目标/资源/费用不与处方采购挂钩。
