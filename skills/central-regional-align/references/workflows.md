# 协作对齐 — 场景工作流

> 纵向（中央↔区域）：场景 1–3。横向（跨部门）：场景 4–7。

# 纵向：中央 ↔ 区域

## 场景 1：策略下达包（中央 → 区域）

**输入**：中央品牌/cycle 策略、目标、物料、活动指引。

**步骤**：
1. **提炼要点**：从策略文档提取"打什么、为什么、目标是什么"——去掉中央内部语境，留区域用得上的。
2. **明确区域动作项**：区域要接住哪些动作（落地计划、客户覆盖、活动执行），每项标"要做什么/何时/交付什么"。
3. **附材料与合规状态**：物料标 MLR 状态；未审材料明确"仅供了解、不得对外"。
4. **结构化成下达包**：让区域读完无歧义、知道下一步（见 `templates/rollout-package.md`）。

**产出**：策略下达包。区域接住落地走 `regional-plan`。

## 场景 2：对齐会组织

**输入**：待对齐议题（策略下达 / 季度 review / 问题澄清）。

**步骤**：
1. **定议程与目标**：这个会要对齐什么、产出什么决议。
2. **备材料**：下达包 / 区域进展 / 待决问题清单。
3. **会中记录决议与 action**：每个 action 定责任人、时间、交付物。
4. **会后跟踪**：action 落实跟踪（接场景 3 闭环）。

**产出**：对齐会议程 + 会议纪要/action list（议程见 `templates/alignment-agenda.md`；纪要走 `meeting-minutes`）。

## 场景 3：反馈回流与闭环（区域 → 中央）

**输入**：区域执行反馈、资源缺口、一线洞察、竞品动态。

**步骤**：
1. **归集分类**：执行进展 / 问题与缺口 / 一线洞察 / 竞品信号。
2. **提炼上传**：洞察部分走 `field-insight-synthesis` 提炼 so-what；脱敏个案与 PII。
3. **结构化回流**：明确"反馈什么、建议中央做什么、需要什么回应"（见 `templates/feedback-loop.md`）。
4. **跟踪闭环**：登记中央回应（采纳/调整/说明），不让反馈石沉大海。

**产出**：反馈回流 brief + 闭环跟踪表。对上正式呈现可用 `bilingual-report`。

> 双向不失真、反馈有闭环。敏感数据脱敏，不外传、不进 git。

# 横向：跨部门协作

> 横向方法论（协作地图、例会效率原则、升级机制）见 `references/cross-functional.md`。

## 场景 4：品牌团队 / 跨部门例会

**输入**：会议目的、参会部门（Marketing/Medical/Access/销售/PDMA/财务等）、待议题。

**步骤**：
1. **定议程与产出类型**：每个议题标清是"讨论 / 决策 / 信息同步"，分配时间。
2. **各方预读**：会前 24h 发议程 + 预读材料，避免会上现读。
3. **会中记录行动项**：每议题给明确结论；离题进"停车场（Parking Lot）"。
4. **会后 24h 纪要**：纪要走 `meeting-minutes`；行动项进追踪表（场景 5）。

**产出**：例会议程 + 行动项清单（议程见 `templates/cross-functional-agenda.md`）。

## 场景 5：行动项追踪

**输入**：各次跨部门会议产生的 action items。

**步骤**：
1. **归集**：每条 action 标来源会议、责任人、截止日、当前状态。
2. **逾期预警**：按截止日排序，逾期项标注并给建议行动。
3. **下次会先追**：下次例会开场先过未完成项，不让 action 沉底。
4. **闭环**：完成/延期/取消均记录，延期说明原因与新期限。

**产出**：行动项追踪表（见 `templates/action-item-tracker.md`）。

## 场景 6：RACI 分工

**输入**：一件需多部门协作的事 / 一组任务。

**步骤**：
1. **列任务 × 角色**：行是任务，列是参与方。
2. **分配 RACI**：每项标 R（执行）/A（负责）/C（咨询）/I（知会）。
3. **校验**：每项任务**有且仅有一个 A**；消除"没人负责"和"多头负责"。
4. **确认**：与各方确认认领，避免事后推诿。

**产出**：RACI 矩阵（见 `templates/raci-matrix.md`）。

## 场景 7：Stakeholder 沟通

**输入**：需跨部门通知/协调的事项。

**步骤**：
1. **定对象**：按协作地图（`references/cross-functional.md`）与 RACI 的 C/I 角色定收件人。
2. **选场景**：通知 / 协调请求 / 升级 / 进展同步。
3. **起草** → 委派 `email-authoring`（本技能只定"发给谁、说什么要点"）。

**产出**：沟通对象清单 + 要点。实际邮件交 `email-authoring`。

> 跨部门协作：结论清晰、行动有主、追踪到底。共享的客户/销售数据脱敏，不外传、不进 git。
