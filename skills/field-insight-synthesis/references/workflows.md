# Field Insight Synthesis — 场景工作流

## 场景 1：反馈汇总提炼

**输入**：一线反馈原始素材（拜访记录、群消息、口头反馈、观察）。

**步骤**：
1. **收集归集**：把散落反馈汇到一处，标注来源（哪个区域/成员/时间）。
2. **分类**：按反馈类型（客户异议/竞品动态/市场信号/执行反馈）归类。
3. **辨信号vs噪音**（见 `methods.md`）：反复出现、跨区一致、有业务影响的是信号；个案/情绪/孤例是噪音，标注但不放大。
4. **提炼 so-what**：每组信号问"这意味着什么？对策略/执行有什么影响？"
5. **给行动建议**：可行动的下一步，标明该谁做。

**产出**：结构化洞察（见 `templates/insight-summary.md`）。

## 场景 2：竞品动态汇总

**输入**：一线观察到的竞品动作（新数据宣讲、地面活动、话术、价格动作）。

**步骤**：
1. 归集竞品信号，标来源与可信度。
2. **来源合规校验**：只保留合法公开来源/合规渠道获取的信息，剔除来路不明或涉密内容。
3. 初步分类（产品/学术/市场/准入维度）。
4. **交接**：把结构化竞品信号交 `competitive-brief` 做深度分析与应对。

**产出**：竞品信号清单（供 competitive-brief 输入）。

## 场景 3：回流中央 brief

**输入**：提炼后的洞察。

**步骤**：
1. **定接收方**：这条洞察该给谁（中央市场/物料/竞品/策略）。
2. **按 brief 结构组织**：洞察 → 证据（趋势非个案）→ 影响 → 建议 → 建议接收方。
3. **脱敏**：去客户 PII 与个案细节，聚焦趋势。
4. 跨区/对上需要时用 `bilingual-report` 转双语。

**产出**：洞察回流 brief（见 `templates/insight-brief.md`）。

> 脱敏个案、只用合规竞品来源、产品声明走 MLR。
