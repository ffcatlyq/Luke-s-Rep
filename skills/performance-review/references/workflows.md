# Performance Review — 场景工作流

## 场景 1：达成分析

**输入**：目标数、实际数（销量/份额/覆盖），时间周期，可用维度。

**步骤**：
1. **确认数据口径**：目标基准、时间范围、指标定义（销量？出货？份额？）。口径不清先问。
2. **算总体达成率** = 实际 / 目标。
3. **多维拆解**（用 `data-analysis` 做透视）：按大区 / 医院分级（C30/T70/T300）/ 产品 / 成员分别看达成，定位拖后腿与领先的部分。
4. **标注异常**：哪些维度显著高于/低于均值。

**产出**：达成概览表 + 分维度达成 + 异常点清单。

## 场景 2：差距归因

**输入**：达成分析结果（尤其未达成的维度）。

**步骤**：
1. **量价结构分解**：差距来自量（覆盖/渗透不足）、价、还是产品结构变化？见 `attribution-framework.md`。
2. **覆盖漏斗**：目标医院覆盖率 → 准入 → 处方转化，哪一环掉了。
3. **5 类归因**：市场/竞争（外部）、覆盖执行、团队能力、资源投入、产品/准入。区分可控与不可控。
4. **定位可改进项**：聚焦可控且影响大的。

**产出**：归因表（差距 → 原因 → 可控性 → 优先级）。

## 场景 3：复盘会材料

**输入**：达成分析 + 归因结果 + 下一步想法。

**步骤**：
1. 按复盘包结构组织（见 `templates/review-deck.md`）：达成概览 → 亮点 → 差距与归因 → 行动计划 → 资源需求。
2. 行动计划每条含：做什么、谁负责、何时、如何衡量。
3. 需要对上汇报时，用 `bilingual-report` 转中英双语。
4. 需要图表时，让 `data-analysis` 生成，嵌入材料。

**产出**：复盘会材料（内部）。

> 全程数据敏感：材料标注内部使用，不外发。
