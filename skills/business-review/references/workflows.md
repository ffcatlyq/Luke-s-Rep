# Business Review — 场景工作流

## 场景 1：例会框架搭建

**输入**：例会类型（月度 MBR / 季度 QBR）、周期、参会范围。

**步骤**：
1. **选板块**：按需选业绩/市场/客户/洞察/下步（见 SKILL 板块表）。
2. **每块定负责人与数据源**：谁提供、从哪拿（标注敏感数据）。
3. **定时间盒**：每板块分配时长，避免例会失控。
4. **搭空框架**：让各方按框架填输入（见 `templates/review-agenda.md`）。

**产出**：例会框架/议程。

## 场景 2：例会包整合

**输入**：各板块输入（达成数据、活动产出、客户覆盖、洞察）。

**步骤**：
1. **汇总各板块**：达成接 `performance-review`；洞察接 `field-insight-synthesis`；活动接 `regional-event`。
2. **提炼要点**：每板块只留"结论 + so-what + 证据"，不堆原始数据。
3. **整合成一份 deck**：逻辑连贯——达成如何 → 为什么 → 市场/客户情况 → 下步。
4. **可双语**：对上/正式呈现走 `bilingual-report`。

**产出**：业务例会包（见 `templates/review-pack.md`）。

## 场景 3：例会决议跟踪

**输入**：例会决议与 action。

**步骤**：
1. **登记决议**：每条 action 定责任人、时间、交付物。
2. **跨周期跟踪**：下次例会开场先回顾上次 action 完成情况。
3. **闭环**：完成/延期/取消，均记录并说明。

**产出**：action 跟踪表（见 `templates/action-tracker.md`）。

> 数据敏感（销售/客户/成员）——内部使用，脱敏个案，不外传、不进 git。
