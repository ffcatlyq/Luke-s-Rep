# 业务例会方法论

## 例会节奏（参考）

| 类型 | 频率 | 焦点 | 时长 |
|---|---|---|---|
| MBR 月度 | 每月 | 达成进度、执行纠偏、短期 action | 短平快 |
| QBR 季度 | 每季 | 全景回顾、策略校准、下季规划 | 深度 |

## 整合框架：从散到整

例会最大的坑是"各念各的 PPT"。整合逻辑：

```
达成如何（业绩）→ 为什么（归因，接 performance-review）
→ 市场/客户在发生什么（活动+覆盖+洞察）
→ 所以下步做什么（计划+资源+action）
```

每板块只留 **结论 + so-what + 支撑证据**，把原始数据放附录。

## 常见坑

| 坑 | 对策 |
|---|---|
| 数据堆砌无结论 | 每块先给结论，再给证据 |
| 各板块割裂 | 用"达成→归因→市场→下步"串成一条线 |
| 只回顾不决议 | 每次例会产出明确 action（谁/何时/什么）|
| action 不跟踪 | 下次例会开场回顾上次 action（场景 3）|
| 报喜不报忧 | 问题与缺口如实呈现，才有价值 |

## 板块输入来源速查

| 板块 | 接哪个技能 |
|---|---|
| 业绩达成/归因 | performance-review |
| 市场活动产出 | regional-event / regional-plan |
| 客户覆盖/分层 | customer-segmentation |
| KOL/讲者运营 | speaker-management |
| 一线洞察/竞品 | field-insight-synthesis / competitive-brief |
| 对上双语呈现 | bilingual-report |

## 合规

- 销售/客户/成员数据敏感——内部使用，不外传、不进 git。
- KOL/讲者运营不与处方采购挂钩。
- 产品声明须循证、经 MLR。
