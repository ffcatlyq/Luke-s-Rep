# 核心功能详解

## 功能一：项目启动与规划

当用户说"启动项目"、"新建项目"、"项目规划"时：

1. **项目定义**：
   - 项目名称、目标、范围
   - 项目类型（参考 SKILL.md 适用项目类型表）
   - 关键日期和里程碑
   - 成功标准

2. **WBS 分解**：
   - 按 Phase 分解工作包
   - 每个工作包定义：任务描述、负责人、截止日、依赖关系
   - 识别关键路径

3. **RACI 制定**：
   - 识别所有 stakeholder 和角色
   - 为每项任务分配 RACI（Responsible/Accountable/Consulted/Informed）
   - 确保每项任务有且仅有一个 A（Accountable）

4. **风险评估**：
   - 识别潜在风险（时间、资源、合规、外部依赖）
   - 评估影响和概率
   - 制定缓解措施和应急计划

5. **预算编制**：
   - 费用分类和估算
   - 资金来源确认
   - 审批流程

6. **输出**：在 `outputs/projects/<项目名>/` 下创建项目文件（复制 `templates/` 模板）。含敏感信息，内部使用不进 git。

## 功能二：进度提醒与待办

当用户说"今天项目有什么安排"、"本周待办"、"项目提醒"时：

1. 读取项目时间线，根据当前日期定位所在 Phase
2. 生成提醒报告：

```
📅 [日期] / 距[关键日期]D-XX 天 / 当前 Phase: [Phase 名称]

【本周待办】（按截止日期排序）
- [ ] 任务A — 负责人 — 截止日 — 当前状态
- [ ] 任务B — ...

【已逾期未完成】⚠️
- 任务X — 原定截止日 — 逾期N天 — 建议行动

【未来 1-2 周预警】
- 下周需启动：任务C、任务D
- 关键里程碑：XXX（距今N天）

【需要你今天跟进的】
- 按 RACI 区分"你需要亲自做的"和"你需要跟进别人做的"
```

**输出原则**：
- 只展示与当前时间相关的任务
- 逾期任务标注并给出建议行动
- 按 RACI 标注负责人

## 功能三：进度反馈与更新

当用户反馈进度（如"XXX 已完成"、"XXX 搞定了"、"XXX 已提交"）时：

1. **解析反馈**：提取任务名称、新状态、附加信息
2. **更新项目文件**：更新时间线中对应任务的状态
3. **提示下一步**：
   - 下游依赖任务
   - 需要通知的 stakeholder（参考 RACI 中的 I 角色）
   - 是否触发新风险或需要调整时间线

## 功能四：风险监控

当用户说"风险检查"、"项目风险"时：

1. 读取风险登记表
2. 评估当前风险状态（是否有新触发的风险）
3. 检查缓解措施执行情况
4. 识别新风险（基于进度偏差、外部变化）
5. 更新风险登记表

## 功能五：Stakeholder 沟通（起草委派原子技能）

当用户说"起草邮件"、"通知 XXX"、"会议纪要"时——**本技能只做"项目侧的谁/什么/用哪个模板"，实际起草与投递委派原子技能**：

1. **确定沟通对象**：参考 RACI 矩阵（I/C 角色）+ stakeholder 沟通计划确定收件人。
2. **选场景与模板**：按沟通场景选 `templates/email-templates.md` 里的项目专属模板（项目启动/进度更新/风险预警/邀请确认等），填入项目具体信息作为素材。
3. **邮件起草** → 委派 `email-authoring`。
4. **会议纪要** → 委派 `meeting-minutes`（transcript→结构化双语纪要、参会人匹配、敏感过滤）。

> 分工：**"这封沟通面向谁、属于项目哪个节点、用哪个项目模板"是项目管理职责，留本技能**；
> **"把它写成得体的邮件/规范的纪要"是通用能力，交原子技能**。

## 功能六：项目收尾与复盘

当用户说"项目复盘"、"总结"、"经验教训"时：

1. **完成度检查**：核对所有任务是否完成
2. **目标达成评估**：对照项目启动时的成功标准
3. **洞察汇总**：收集项目过程中的关键发现（可回流 `field-insight-synthesis`）
4. **经验教训**：What went well / What could be improved / Action items
5. **文档归档**：整理项目文档，归档到 `outputs/projects/`

## 项目实例存放

通用项目管理能力（本技能 + 模板）进 git；**具体项目实例含敏感信息，存 `outputs/`，不进 git**。

```
skills/project-management/        ← 通用能力和模板（进 git）
    ├── SKILL.md
    ├── references/
    └── templates/                ← 通用模板，供项目复制使用

outputs/projects/                 ← 具体项目实例（敏感信息，不进 git）
    └── <项目名>/
        ├── charter.md            ← 复制并填充的项目章程
        ├── wbs.md                ← 时间线/WBS
        ├── raci.md               ← 职责矩阵
        ├── risk-register.md      ← 风险登记
        └── budget.md             ← 预算
```

**新建项目流程**：
1. 复制 `templates/` 下的通用模板到 `outputs/projects/<项目名>/`
2. 定制模板内容，填入项目特定信息
3. markdown 文件作为 agent 的项目参考与进度追踪源
