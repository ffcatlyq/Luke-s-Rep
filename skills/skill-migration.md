# 技能：从通用库迁移技能（Skill Migration）

> 角色：**赋能**。把外部通用技能库（如 silicon-hitchhiker）里的技能，安全地迁移到本仓复用。核心是**分档筛选 + 两段式落地（先原样复用、再逐步适配）**，不一步到位、不照抄会过期的清单。
> 属**通用引擎**，跨治疗领域与角色复用。

## 触发条件
- "从 silicon / 通用库挑技能过来""看看哪些技能能复用""把 X 技能搬进来"
- 搭建新团队智能体时的"挑技能"环节（由 `bootstrap-team-agent.md` 调用）

## 输入（缺失则追问）
- 源技能库地址（如 silicon-hitchhiker 的 repo URL）
- 目标角色/场景（PM？MA？决定相关度判断）
- 本次范围：只挑强相关的，还是含某类全搬

## 核心原则（先记住这几条）
1. **现场盘点，不抄清单**：源库会变。每次都 clone 源库、现场列出它当前有哪些技能，**不要**把某一时刻的技能清单写死进任何文档。
2. **两段式落地**：先"原样复用"快速落地并标注待适配，再按需"逐步适配"。别想一次到位。
3. **依赖看实测，不看声明**：`requires.txt` 常多列或写旧。以脚本实际 `import`/调用为准判断真实依赖。
4. **落地前扫凭据**：外部库常残留真实密钥/token。搬入后、推送前必须扫（见"安全闸门"）。

## 任务流

### 阶段 A：盘点与分档
1. **clone 源库**，列出全部技能及各自 `SKILL.md` 的 description（现场取，不凭记忆）。
2. **对照本仓已有技能**，避免重复搬。
3. **按"相关度 × 移植成本"分档**：
   - 移植成本看依赖：**纯 prompt（零依赖）< 带脚本但用公开 API < 依赖账号/私库/OAuth 底座**。
   - 相关度看目标角色：这个技能是不是该角色的高频场景。

   | | 低成本（纯 prompt / 公开 API） | 高成本（需账号/基建） |
   |---|---|---|
   | **强相关** | 🟢 第一梯队：优先搬 | 🟡 第二梯队：值得但要投入 |
   | **弱相关** | 视情况 | ⚪ 一般不搬 |
4. **产出分档清单**给用户拍板搬哪些、搬到什么程度。**不擅自全搬**——弱相关技能会污染仓库。

### 阶段 B：原样复用（快速落地）
1. **原样复制**技能目录（含子文件/脚本）到目标位置：
   - 纯 prompt 业务技能 → 转成本仓 `skills/*.md` 业务格式（见阶段 C）。
   - 带脚本的工具技能 → `.claude/skills/<name>/`，保留 Claude Code 结构。
2. **实测依赖链**，不信 `requires.txt` 表面：
   - grep 脚本实际 `import` / `subprocess` 调用，画出真实依赖图。
   - 检查相对路径定位（如 `parent.parent/xxx`）在新位置是否成立。
   - 声明的依赖若脚本根本不用，**不搬**（避免拖入无关重依赖）。
3. **登记并标注状态**：`skills/README.md` 加行，标 `⏳ 原样搬入待适配` 或 `🔧 基建就绪待授权`，与已适配技能区分。
4. **安全闸门**（见下）后提交。

### 阶段 C：逐步适配（按需精修）
对确定要长期用的技能，逐个适配（不必一次全做）：
1. **转本仓格式**：业务技能套本仓结构——触发条件 / 输入 / 任务流 / 产出模板 / 合规检查 / 关联。
2. **挂本仓护栏**：加 PM/MA 合规检查、`outputs/` 归档、知识包挂载（`knowledge-packs/<领域>/`）。
3. **剥离外部账号依赖为"可选"**：核心逻辑走纯 prompt，账号增强（Gmail 推送等）降级为可选路径。
4. **保留精华、砍无关**：源技能里通用的精华（如反-AI 写作规则、保守 attribution、校对铁律）保留；与目标角色无关的平台机制精简掉。
5. **不硬编码产品知识**：运行时从知识包读，保证跨领域通用。
6. **更新状态标记** ⏳/🔧 → ✅，登记更新。

## 安全闸门（推送前强制）
外部库常残留真实凭据——**这不是假设，是发生过的事**。搬入后、`git push` 前必扫：
```bash
grep -rnE "GOCSPX-|ya29\.|AIza[0-9A-Za-z_-]{20,}|-----BEGIN|apps\.googleusercontent\.com" <搬入目录>
```
- 命中真实 client_id/secret/token/私钥 → **替换为 `<YOUR_XXX>` 占位符**，绝不入库。
- 已 commit 未 push 时用 `git commit --amend` 修正，避免凭据留在历史。
- `.gitignore` 兜底凭据文件（`oauth_client.json`/`google_token.json`/`cookies.json`/`*.pem`/`*.key`）。
- 依赖 GitHub 推送保护做最后一道网，但不能只靠它——本地先扫。

## 验收清单
- [ ] 分档清单经用户确认，未擅自全搬
- [ ] 真实依赖以实测为准，未搬入脚本不用的无关重依赖
- [ ] 相对路径/import 链在新位置实测可加载
- [ ] 推送前凭据扫描通过，无真实密钥入库
- [ ] `skills/README.md` 已登记且状态标记准确（⏳/🔧/✅）
- [ ] 适配后的技能挂了合规护栏、不硬编码产品知识
