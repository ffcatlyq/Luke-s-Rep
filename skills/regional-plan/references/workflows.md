# Regional Plan — 场景工作流

## 场景 1：中央策略解读

**输入**：中央 brand plan / cycle plan / 战术包。

**步骤**：
1. **提取核心**：中央的目标（要达成什么）、策略（怎么赢）、关键战术（做哪些动作）、关键信息（core messages）。
2. **标注不可变 vs 可本地化**：品牌定位、核心信息、合规边界=不可变；执行方式、渠道、节奏、资源=可本地化。
3. **列本地化清单**：哪些点需要结合本区域调整。

**产出**：策略解读 + 本地化清单。

## 场景 2：区域计划制定

**输入**：策略解读、区域格局、客户覆盖、团队资源。

**步骤**：
1. **目标下沉**：中央目标 → 本区域目标（接 `performance-review` 的目标分解思路）。
2. **叠加区域格局**：读 `regions/china-market.md`——本区医院分布、准入、竞争差异。
3. **定客户覆盖**：接 `customer-segmentation`——本区分层与覆盖 gap。
4. **配资源与时间线**：接 `territory-management`——辖区、产能、预算；排关键里程碑。
5. **组织成计划**：按 `templates/regional-plan.md` 结构。

**产出**：区域执行计划。

## 场景 3：计划-资源校验

**输入**：区域计划草案、团队产能与预算。

**步骤**：
1. 算计划所需投入（拜访人次、活动场次、费用）。
2. 对比团队产能与预算，识别缺口。
3. 缺口处理：优先级取舍、向中央申请资源（走 `central-regional-align`）、或调整目标。

**产出**：校验后的计划 + 缺口/取舍说明。

> 数据敏感，产出默认内部使用；推广内容走 MLR，活动走 regional-event 合规留痕。
