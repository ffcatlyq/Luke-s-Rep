# 技能：搭建业务团队智能体（Bootstrap Team Agent）

> 角色：**赋能**。为一个新业务角色（市场部 PM、医学部 MA 等）从零搭一套 Ona 工作智能体仓库——架构 → 挑技能 → 复用 → 适配 → 基建 → 整理 → onboarding。
> 这是一次性、低频、高风险的工程。本 playbook 固化的是**决策判断与护栏**，不是流水账。属**通用引擎**，跨角色复用。

## 触发条件
- "给 MA / 某团队从零搭一套智能体""照 PM 这套给医学部做一份""新建一个业务角色的仓库"
- 已有一套成熟仓库（如本 PM 仓）作参照，要复制方法论到新角色

## 怎么用这份 playbook（重要）
- 这是**引导手册，不是脚本**。阶段顺序是常见路径，不是圣旨——真实项目里会调整（如先建知识包再挑技能）。
- 每阶段先过**决策闸门**（该停下问用户的点），再执行。
- **不枚举易变信息**：源技能库有哪些技能、什么路径，一律**现场盘点**，别信任何写死的清单（包括本文件）。
- 每个大阶段完成后**产出落盘 + 提交**，作为下一步出发点，不一口气吞完。

## 六阶段 + 决策闸门

### 阶段 1：架构骨架
搭"通用引擎 + 可插拔知识包"的分层（见参照仓 `docs/architecture.md`）。
- **通用引擎**（跨角色不变）：`AGENTS.md`（行为总纲/角色/合规红线）、`skills/`（业务技能）、`compliance/`（合规护栏）。
- **可插拔知识包**：`knowledge-packs/<领域>/`，含 `_TEMPLATE` 供扩展。
- **决策闸门**：这个角色的三种身份权重是什么？（PM 执行导向、MA 可能学术/证据导向）→ 决定 `AGENTS.md` 里角色与 KPI 的侧重。**先和用户对齐角色定位，再写 AGENTS.md。**

### 阶段 2：挑技能（调用 `skill-migration.md`）
从通用库（silicon-hitchhiker 等）筛选可复用技能。
- **完全走 `skill-migration.md`**：clone 源库现场盘点 → 按"相关度 × 移植成本"分档 → 产出清单给用户拍板。
- **决策闸门**：搬哪些、搬到什么程度？**不擅自全搬**，弱相关技能会污染仓库。

### 阶段 3：原样复用（快速落地）
把选中技能原样搬入并登记，标注 `⏳ 待适配`（细节见 `skill-migration.md` 阶段 B）。
- **决策闸门**：先全落地再适配，还是边搬边适配？默认**先原样落地**，让用户尽快看到全貌，再决定精修哪些。

### 阶段 4：逐步适配（按需精修）
对确定长期用的技能，套本仓格式、挂合规/知识包、剥离账号依赖为可选（细节见 `skill-migration.md` 阶段 C）。
- **决策闸门**：哪些现在适配、哪些留待用？不必一次全做——**按使用频率排序**，高频先适配。

### 阶段 5：环境基建（按需）
需账号/OAuth/引擎的技能，搭好脚本 + 依赖自动化 + 凭据兜底 + 上手文档。
- 依赖装到 `.ona/automations.yaml`（环境启动自动装）；重依赖（如幻灯引擎）按需装。
- **实测打通**：import 链、脚本 `--help` 能跑（缺的只是授权）。
- **决策闸门**：**凭据/授权归用户，不代办**。基建搭到"待授权"状态，写清上手文档（如 `docs/google-workspace-setup.md`），OAuth 由用户手动完成。

### 阶段 6：仓库整理 + Onboarding
交付前把仓库收拾干净、写好新人指南。
- **整理**：见下"仓库整理闸门"。
- **Onboarding**：写 `ONBOARDING.md`（面向 fork→建 Ona 环境的同事）——是什么/建环境/5 分钟跑通首个任务/高频用法/需授权能力/换领域/合规须知/FAQ。示例 prompt **用知识包里真实存在的产品名**，让人照抄即通。

## 仓库整理闸门（阶段 6 关键判断）
这些是踩过的坑，逐条过：
- **技能分散**：多处存放（`skills/` vs `.claude/skills/`）**不必物理合并**——统一逻辑索引即可（一张总览表 + 各处 README 指向）。物理合并易破坏工具技能的脚本相对路径。
- **大文件/派生物入库**：删可重建的派生物前，**先实测"能无网重建 + 与原文件比对一致"**（如 md5），确认是纯派生物再删、加 `.gitignore`。**不确定就不删**。爬取的源快照（重建需账号/联网）必须保留。
- **诡异文件名/前缀**：先查它是不是**功能性设计**（如 asset-id 去重前缀），别当噪声删——删了可能破坏索引引用。改前先确认无冲突、无引用依赖。
- **凭据审计**：全库扫真实密钥/token（见 `skill-migration.md` 安全闸门）。
- **文档过时**：整理时顺手改掉过期描述（如"某引擎报红"其实已修好）。

## 全局协作纪律
- **先对齐再执行**：每个大阶段开工前，复述目标 + 拆步骤 + 亮假设 + 待确认项，等用户确认（对齐 `AGENTS.md` 第 4 节）。
- **澄清打在正文**：选项用编号列在回复正文，不用弹窗式工具。
- **分步落盘**：每阶段产出中间物、提交，长会话防跑偏。
- **不注水不臆造**：读不准就说"待核实"，不编数据/清单。

## 验收清单
- [ ] AGENTS.md 角色定位/KPI 与目标团队对齐（非照抄 PM）
- [ ] 技能经分档筛选、用户拍板，未擅自全搬
- [ ] 搬入技能已登记、状态标记准确（⏳/🔧/✅）
- [ ] 需授权的基建搭到"待授权"，凭据留给用户、文档写清
- [ ] 仓库整理各闸门已过（派生物验证、凭据扫描、文档更新）
- [ ] `ONBOARDING.md` 覆盖 fork→建环境→跑通首个任务，示例用真实产品名
- [ ] 全程分阶段提交，每阶段可独立验证
