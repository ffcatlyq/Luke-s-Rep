# Regional Event — 场景工作流

## 场景 1：活动策划

**输入**：活动目的、目标受众、预算范围、时间窗口。

**步骤**：
1. **定目标**：这场会要达成什么（学术传播/客户关系/新数据发布）。
2. **选形式与规模**：科室会 / 区域学术会 / 卫星会（见 `methods.md` 活动类型）。
3. **讲者规划**：需要哪些讲者，走 `speaker-management` 做遴选（学术资质、FMV、利益冲突）。
4. **内容规划**：议程、讲题、材料——材料走 `promo-material-mlr` 送审。
5. **预算与合规预检**：费用合规范围、留痕要求；填合规预检清单（见 `methods.md`）。

**产出**：活动策划案（见 `templates/event-plan.md`）。

## 场景 2：执行清单

**输入**：策划案。

**步骤**：
1. **拆全流程**：会前（审批/邀请/物料/场地）→ 会中（签到/执行/记录）→ 会后（归档/费用/跟进）。
2. **每项定责任人与时间**。
3. **标留痕点**：哪些环节必须留档（立项审批、讲者合同、签到表、费用凭证、材料 MLR 记录）。

**产出**：执行清单（见 `templates/execution-checklist.md`）。

## 场景 3：会后跟进

**输入**：活动执行记录。

**步骤**：
1. **合规归档**：签到、费用、讲者劳务、材料 MLR 记录全部归档备查。
2. **效果评估**：参会情况、互动质量、目标达成（见 `methods.md`）。
3. **洞察回流**：会上收集的客户反馈/竞品信息 → 走 `field-insight-synthesis`。
4. **后续动作**：参会客户的跟进计划。

**产出**：会后报告（见 `templates/post-event-report.md`）。

> 全程强合规：讲者/内容/费用留痕，不与处方采购挂钩，PII 数据不外传。
